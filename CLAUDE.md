# Naafiri — notes pour Claude

App personnelle (un seul utilisateur) pour **compter les calories**, inspirée de **Yazio** : journal des repas, macros, poids, objectifs. Même architecture que mes PWA **MangaTime** (`itsj1/MangaTime`) et **Muscu** (`itsj1/FitnessTracker`).

- En ligne : https://itsj1.github.io/Naafiri (GitHub Pages, branche `main`).
- Tout doit rester **gratuit** : pas de serveur, pas de service payant.
- Langue de l'interface, des commentaires et des messages de commit : **français**, avec tutoiement et apostrophes typographiques (’).

## Architecture

- PWA en **un seul fichier `index.html`** (CSS + JS inline, sans framework ni build), plus `sw.js`, `manifest.json`, les icônes, `zxing.min.js` et `ciqual.json` (table CIQUAL, ~700 Ko, ~220 Ko compressé ; préchargée par le service worker).
- Code **compact** comme les autres projets (noms courts `S`, `F`, `$`, `esc`, `uid`, une fonction par ligne, template literals) : ne pas reformater.
- `sw.js` : réseau d'abord, cache en secours après 3 s. **Incrémenter `CACHE` (`naafiri-vN`) à chaque version publiée, et `APPV` (même N) dans `index.html`** : le numéro s’affiche en bas des Réglages, pour vérifier que le téléphone a la dernière version. Il n'intercepte que les fichiers du site (jamais Open Food Facts ni `api.github.com`).
- `zxing.min.js` : `@zxing/library` 0.21.3 (UMD, licence Apache 2.0), chargé seulement au premier scan quand le navigateur n'a pas `BarcodeDetector` (iPhone). Ne pas le modifier.
- **La page ne défile pas** : `main#app` est fixé plein écran et c'est lui qui défile (le rebond d'iOS ne bouge pas la barre d'onglets).
- Rendu : `render()` reconstruit `#app` (vue) et `#dlg` (feuille ouverte) en `innerHTML` ; toutes les actions passent par `data-a=…` dans un seul écouteur de clic. Toujours échapper le texte avec `esc()`.
- Onglets dans l’ordre **Progrès · Journal · Profil** (Journal au milieu, ouvert au démarrage).
- État d'affichage : `TAB` (`jour` / `prog` / `prof`), `SUBV` (sous-page : `add`, `tpl` éditeur d’un repas enregistré (brouillon `TPE`), `meal` aliments du repas `ADDM`, `nut` détail nutritionnel du jour ou d’un repas `NUTM` ('all' ou b/l/d/s), `my` mes aliments ; pile `SST` pour revenir à la sous-page précédente), `F` (feuille ou pop-up : `tpl` repas enregistré à ajouter, `copy` copier un repas ou une journée, `qty`, `qa`, `cf`, `prof`, `goal`, `scan`, `cfg` réglages, `ask`), `CUR` (jour affiché `AAAA-MM-JJ`), `ADDM` (repas en cours d'ajout).
- Les champs des feuilles écrivent dans `F.d` via `data-fd=…` (sans re-rendu) ; les bulles de choix passent par `data-a=fset data-f=… data-v=…`.
- Sous-pages : `openSub()` + `history.pushState`, retour par `popstate` ; transitions `slide()` (View Transitions API, repli en animation de `#app`).
- Bandeaux « Annuler » : `toast(msg, undo)` dans `#toasts`, 4 s, 3 max.
- Gestes horizontaux (`HZ`) : ligne d’aliment `.sw` glissée vers la gauche → poubelle (`edel`, `delEntry()`) ; bulle du jour `#sumc` glissée → jour précédent / suivant ; **retour en glissant depuis le bord gauche** (24 px) sur toutes les sous-pages, comme MangaTime : la page suit le doigt, repart si > 35 % de l’écran ou geste rapide (`NOSL` saute l’animation de `slide()`). Le clic qui suit un glissé est ignoré (`NOCL`).
- `localStorage['naafiri-ui']` (`UI`, propre à l’appareil, non synchronisé) : repas dépliés dans le Journal (`UI.o[m]`).

## Données

- `localStorage['naafiri-v1']` → `S = { days, foods, wt, tp, prof, del, cfg, sha }`.
- `tp[id]` (**Mes repas**, id `t:<uid>`) = `{ id, n, pt? (nombre de parts : > 1 = **recette**), it:[{ fid, n, b, q, un, nb, svn, k, p, c, f }], u }`. Une recette devient un aliment virtuel `tp:<id>` (`tpFood()` : valeurs pour 100 g sur le poids total, portion « 1 part », nutriments détaillés cumulés) : elle s’ajoute au journal comme une seule entrée (1 part, ½ part… avec les roulettes), jamais copiée dans `foods` : ensembles d’aliments préconfigurés, synchronisés (fusion selon `u`, suppressions datées dans `del.t`).
- `days[AAAA-MM-JJ] = { e:[entrées], g? (objectif kcal du jour, posé par `stampGoals()` sur les jours passés notés juste avant un changement d’objectif ; lu par `goalsFor(k)`, sinon objectif actuel), u }` (un ancien champ `w`, l’eau retirée, peut traîner : l’ignorer).
  - Entrée : `{ id, fid, n, b, m (b/l/d/s), q (grammes), un (unité : 'g', 'kg', 'ml', 'l', ou portion 'p' / 'p1', 'p2'… / 'pk' paquet), nb (nombre saisi dans cette unité), svn (nom de la portion), k, p, c, f (pour 100 g, figés au moment de l'ajout), qa? (ajout rapide) }`.
- `foods[id]` : aliments utilisés, favoris et perso. `id` = `off:<code-barres>`, `cq:<code CIQUAL>` (portions courantes déduites du nom par les règles `CQR` / `cqPort()` : 1 banane, 1 assiette de pâtes cuites, 1 verre de lait…), `us:<fdcId USDA>`, `g:<clé>` (ancienne petite table `GEN`, gardée pour les entrées existantes et en secours si `ciqual.json` ne charge pas) ou `my:<uid>`. Champs `n, b, k, p, c, f` (pour 100 g), `sv`/`svn` (portion principale), `ps` (portions en plus `[[nom, g]]`, table `GENP` pour les aliments de base), `pk` (poids du paquet, Open Food Facts), `nu` (tous les nutriments détaillés connus, pour 100 g, en grammes, clés Open Food Facts listées dans `NUTS` ; alcool converti de % vol en g), `su, sf, fi, sa` (anciens champs sucres, saturés, fibres, sel, encore lus par `nv()`), `img`, `ns` (Nutri-Score), `last` (récents), `lq` (dernière quantité utilisée `{un, nb}`, proposée par défaut la fois suivante via `defQ()`, aussi pour le « + » direct ; sans `lq`, la feuille s’ouvre **en grammes** : poids d’une portion, sinon 100 g), `fav`, `my`, `u`.
- `GEN` : table intégrée d'aliments de base (valeurs moyennes). **Ne jamais changer une clé existante** (elle sert d'id), ajouter à la fin.
- `wt[AAAA-MM-JJ] = { kg, u }` ; `prof = { sx, age, h, kg, gw (poids cible), act, obj, pace, kc (0 = auto), mac:{c,p,f} en %, u }` (ancien `wat` ignoré).
- Objectif calorique : Mifflin-St Jeor × activité, ± `pace` × 7 700 / 7 kcal par jour, minimum 1 200 (F) / 1 500 (H), arrondi à 10. Répartition par repas : 25 / 35 / 30 / 10 %.
- Un nouveau champ doit rester optionnel ; ne jamais renommer ni supprimer un champ sans migration.

## Sources

- **CIQUAL 2025 (Anses)**, Licence Ouverte Etalab : ~3 300 aliments génériques avec vitamines et minéraux. `ciqual.json` est généré par `outils/ciqual.py` à partir du JSON complet de la table (format `{v, c:[clés], u:[facteur → g], a:[[code, nom, valeurs…]]}`, valeurs dans l’unité CIQUAL). Chargé à l’ouverture de la page Ajouter (`loadCQ()`, `CQL`, `CQM`), recherche locale `cqMatch()` (tous les mots, singulier = pluriel via `sg()` ; classement : nom qui commence par le premier mot, mots entiers, peu de mots en plus avant la première virgule, aliments courants (avec portions), versions « de tous les jours » de la liste `CQFAV` (pain moyen, œuf cru / dur, riz blanc cuit, lait demi-écrémé UHT…), « aliment moyen », féculents cuits avant crus (`CQCRU`), puis les plus courts). La table se charge 1,5 s après le démarrage ; tant qu’elle n’est pas prête, la section affiche un chargement, et en cas d’échec un message avec « Réessayer » (`CQE`), section « Aliments génériques · CIQUAL » avec « Voir plus » (`CQX`). Le site de l’Anses était en maintenance lors de l’intégration : la source utilisée est une copie publique sur GitHub (`OlivierFitter/ciqual_2025_complete`), recoupée avec la version 2020 (mêmes codes, valeurs cohérentes). À revérifier un jour sur ciqual.anses.fr.
- **USDA FoodData Central** (facultatif, domaine public) : seulement si une clé gratuite est saisie dans Réglages (`S.cfg.usda`, propre à l’appareil). `usSearch()` sur Foundation, SR Legacy et Survey (FNDDS), nutriments par numéro (`USN`). Noms en anglais, section affichée en dernier.

- **Open Food Facts** (sans clé) : recherche `cgi/search.pl` filtrée sur la France (limitée à ~10 requêtes/min : recherche après 700 ms de pause, résultats gardés dans `SC`), un second essai si saturé (`offGet()`), le reste du monde ajouté s’il y a moins de 3 résultats, puis reclassement par nom (`offRank()`). Si la recherche classique est refusée (OFF la ferme aux anonymes quand il y a trop de demandes), secours `salSearch()` : le nouveau moteur `search.openfoodfacts.org` donne les codes (il ne renvoie pas les nutriments de façon fiable), puis chaque fiche est lue avec `api/v2/product/<code>.json` (aussi utilisé par le scan). Mentions CIQUAL, ODbL et USDA dans la feuille Réglages.
- Scan : `BarcodeDetector` natif si disponible (Android), sinon `zxing.min.js` (`MultiFormatReader` + `TRY_HARDER`). Caméra en haute résolution ; on ne lit que la zone du cadre (image recadrée sur un canvas, boucle maison) ; formats EAN-13, EAN-8, UPC-A seulement (UPC-E retiré : faux positifs) ; `gtin()` vérifie le chiffre de contrôle et met l’UPC-A en EAN-13 ; un code n’est accepté que **lu 2 fois à l’identique**. Saisie manuelle en secours (préremplie avec le code si le produit est introuvable). Le code du produit s’affiche dans la feuille quantité.
- Test du scan sans téléphone : Chromium avec `--use-fake-device-for-media-stream --use-file-for-fake-video-capture=<vidéo .mjpeg d’un code EAN-13 généré>`.

## Synchro entre appareils

Fichier `naafiri-data.json` dans un **dépôt GitHub privé** via l'API Contents (même principe que MangaTime et Muscu), jeton fine-grained « Contents : Read and write ». Fusion par journée, par aliment et par pesée selon `u` ; suppressions datées dans `del.f` / `del.w` ; `prof` en bloc. Appeler `touch(obj)` après chaque modification. `cfg` (jeton) reste propre à chaque appareil.

## Écrans

- **Journal** : flèches + bandeau de la semaine (point violet = jour noté, rouge = objectif dépassé), bulle avec anneau des calories restantes et barres glucides / protéines / lipides (glisser à gauche / droite = jour suivant / précédent), quatre repas avec bouton + et flèche pour déplier / replier leurs aliments (repliés par défaut). Pas de suivi de l’eau (retiré à la demande de l’utilisateur).
- **Ajouter** : choix du repas, rond en haut à droite avec le nombre d’aliments de ce repas (ouvre la page `meal` : liste, glisser pour supprimer), recherche (mes aliments → CIQUAL → Open Food Facts → USDA si clé), bouton scan, bulles Récents / Favoris / Mes aliments / **Mes repas** de même largeur (`chipsAdt()`) ; Mes repas : liste (`tplList()`), « + » pour l’ajouter d’un geste au repas choisi, toucher = feuille `tpl` (aliments, total, plusieurs repas cochables, Modifier), bouton « Créer un repas » → éditeur `tpl` (nom, aliments avec quantité modifiable et poubelle, Enregistrer / Supprimer) ; « Ajouter des aliments » de l’éditeur ouvre la page Ajouter en **mode choix** (`PICK()`, sous-page `add` au-dessus de `tpl` dans `SST`) : les aliments vont dans le brouillon, pas dans le journal (feuille quantité avec `F.pick`, `F.ti` pour modifier un aliment). La page d’un repas du journal a « Reprendre le … d’hier » (`cpy`), « Copier vers… » (feuille `copy` : autre jour, autre repas) et « Enregistrer » comme repas (`tpfrom`) ; en bas du Journal, « Copier cette journée vers… » ; « + » pour ajouter directement une portion (coche violette si l’aliment est déjà dans le repas choisi), Ajout rapide, Créer un aliment.
- **Feuille quantité** : kcal, macros et tableau nutritionnel mis à jour en direct (`paintQty()`) ; **deux roulettes** façon iOS côte à côte : quantité (`#wh`, `whVals()` selon l’unité : g / mL **de 1 en 1** jusqu’à 1 000 puis de 10 en 10, deux colonnes centrées et bien espacées, chacune avec son propre rectangle violet `.whb` autour de la valeur choisie) et unité (`#whu` : portions de l’aliment, puis g / kg / mL / L, 1 mL compté comme 1 g, `units()`, `setUnit()` garde le poids) ; défilement aimanté, valeur au centre = valeur choisie ; la feuille ne se ferme pas en les faisant tourner. Pas de bulles de raccourcis ni d’unités (retirées à la demande de l’utilisateur) ; bouton Ajouter juste sous les roulettes, puis plusieurs repas cochables à la fois (`F.ms`, ajout simultané ; en modification l’entrée garde son id dans son repas s’il reste coché) ; favori (étoile), Supprimer en modification.
- **Détail nutritionnel** (page `nut`, comme Yazio) : Calories, Protéines, Glucides (fibres, sucre, sucres ajoutés), Matières grasses (saturées, mono, poly, trans), Autre (alcool, cholestérol, eau, sel, sodium), Vitamines, Minéraux ; « - » si aucun aliment ne donne la valeur. Ouvert par une flèche en bas de la bulle du jour, en bas d’un repas déplié et dans la page du repas. La feuille quantité a aussi « Tout le détail » (`F.full`) : le bouton reste au même endroit, au-dessus du tableau, et seule sa flèche tourne.
- **Progrès** (dans cet ordre) : carte **Macros moyennes · 7 jours** ; **calendrier du mois** (`calHtml()`, mois `CALM`, flèches mois précédent / suivant ; chiffre centré dans un `<b>` en position absolue, car Safari centre mal le texte d’un bouton) : jour noté en **vert** si les calories sont entre 90 % et 110 % de l’objectif (`CALLO` / `CALHI`), **rouge** sinon, neutre si rien de noté ; compte des jours verts / rouges ; toucher un jour l’ouvre dans le Journal ; puis **Calories · 7 derniers jours**. Les 3 bulles de statistiques et la carte Poids (courbe, pesées) ont été retirées à la demande de l’utilisateur, et leur code supprimé : le poids se change dans Profil (les pesées restent dans `S.wt`). Les couleurs du calendrier, les points de la semaine et le graphique utilisent l’objectif **de chaque jour** (`goalsFor()`).
- **Roue dentée en haut à droite** (Journal, Progrès, Profil, `gear()`) : feuille Réglages, même présentation que MangaTime / Muscu (APPARENCE en tête : AUTO / CLAIR / SOMBRE + pastilles de couleur ; titres `.opl` en petites capitales, champs `.soft` dans des cartes, gros boutons `.mi` avec icône : Synchroniser en violet, Exporter ↓ et Importer ↑) : synchro GitHub, clé USDA, sauvegarde JSON et crédits.
- **Profil** : profil, objectifs, mes aliments.

## Design

- Thème **auto / clair / sombre** au choix dans Réglages (section APPARENCE, sélecteur segmenté `.seg2` repris de Muscu ; `S.cfg.theme`, attribut `data-theme` sur `<html>`, `applyTheme()` ; les variables sombres sont sous `@media(prefers-color-scheme:dark){:root:not([data-theme=light])}` **et** `:root[data-theme=dark]`). Couleur principale au choix (`S.cfg.acc`, table `ACCS` : violet par défaut, rose, bleu, vert, orange, turquoise ; `applyTheme()` écrit `--acc`, `--act`, `--tint` dans `<style id=accst>`, en version claire et sombre). Ces deux réglages sont propres à l’appareil (non synchronisés). Accent par défaut : **violet Naafiri** `#a43cf0` (`#b65cff` en sombre). Le thème sombre est volontairement assez clair (fond `#241e2b`, cartes `#302839`) : l’utilisateur trouvait l’ancien trop sombre. Glucides ambre, protéines rose, lipides bleu.
- Toujours passer par les variables CSS de `:root` pour les couleurs.
- Mêmes composants que les autres projets : barre d'onglets en pilule flottante, cartes arrondies, feuilles par le bas (glisser pour fermer), réglages en cartes groupées, icônes SVG maison dans `IC` (en ajouter là plutôt qu'importer une librairie).
- Champs en 16 px (pas de zoom iOS), `inputmode=decimal` pour les chiffres, virgule acceptée.

## Façon de travailler

- L'utilisateur décrit ses demandes en français, souvent à l'oral : reformuler si ambigu, proposer des idées en plus.
- Tester dans Chrome headless (Playwright, vue iPhone, clair et sombre) avec des réponses d'Open Food Facts simulées, vérifier sur captures, puis **pousser directement sur `main`** (le site se met à jour seul).
- Ne jamais committer de jeton GitHub ni de clé USDA.
- Environnement cloud « Naafiri » : il autorise ciqual.anses.fr, data.gouv.fr, Open Food Facts (world et search) et api.nal.usda.gov pour tester avec les vraies API (Playwright : `proxy:{server:process.env.HTTPS_PROXY,bypass:'localhost,127.0.0.1'}`). Ne pas abuser des recherches OFF (limite ~10/min, sinon 503).
